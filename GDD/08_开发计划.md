# 开发计划

技术栈：**Godot 4.x · 2D 像素风**。战斗回合制 + QTE。

---

## 阶段 0 · 灰盒原型（当前）

目标：验证"选卡 → QTE 战斗 → 铺路 → Boss"循环是否好玩。方色块美术，零演出。

1. **单场战斗**：勇者+牧师+主角 vs 1 怪
   - 速度序回合、AI 两队友（最小行为树）、主角动作集
   - 防御 QTE / 闪避 QTE / 暴击 / 完美防御反弹
   - 验收：QTE 手感不疲劳，一场战斗 60~120 秒
2. **循环**：挑战等级旋钮 → 8 步三选一怪卡 → 铺路演出（色块）→ SAN 计量
   - 定神香 / 牧师安抚（-最大HP）/ 战败重试
3. **Boss + 闸门**：父王战（含"留手"Buff）→ 真相时刻 SAN 判定 → 觉醒演出（黑屏文本即可）
4. **数值模拟脚本**：三种策略 × 1000 局，校准凸函数与地板

## 阶段 1 · 垂直切片

- 第一幕完整可玩（3 大轮 + 龙巢 + 觉醒过场）
- 像素美术首批资产（四人小队 + 6 种魔物 + 龙巢场景）
- 安抚鳞纹、低 SAN 噪点、完美防御时停等演出
- 外部试玩 5~10 人，收集：QTE 疲劳度、卡面信息可读性、SAN 代价感知

## 阶段 2 · 第二幕与结局

- 独行战斗 + 血脉树 + 屠杀/放走/追杀系统 + 商人事件
- 四结局全流程 + 伏笔演出
- 魔化线：技能组 + 血洗终章 + 隐藏结局

## 阶段 3 · 打磨量产

- 多周目钩子、成就、音乐音效
- 本地化（中/英）
- 上架目标评估（Steam / itch.io）

## 风险清单

| 风险 | 对策 |
|---|---|
| QTE 疲劳 | 每场战斗 QTE 次数上限；无敌回合可完全跳过反应；辅助模式（QTE 窗口加宽/关闭） |
| 第二幕内容量小于第一幕（独行+纯数值） | 血洗终章压缩设计恰好受益；商人事件/逃跑机制增加战场变化 |
| 剧情演出量大 | 全部文本驱动 + 立绘差分，不做动画过场；鳞纹/噪点等用 shader 解决 |
| 数值失衡 | 模拟脚本先行，机制不改调参数 |
